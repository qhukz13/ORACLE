# 2026-08-22 — PDFs: the text layer, and the one that is a textbook

Requirement 5 of [P5-T2](../../docs/current_task.md). Until now a PDF was classified, counted, and
skipped: `pypdfium2` was a deferred dependency and reading a PDF's bytes as UTF-8 produces a decode
error that looks like a corrupt file rather than a missing feature.

## Verified before written against

The OQ-09 rule — check the wheel loads on this machine before writing code that assumes it does —
applied to the real files rather than a fixture:

```
pypdfium2 5.13.0
   0.7 MB     1 pages     6,008 chars   0.1s  Numpy_Python_Cheat_Sheet.pdf
  33.1 MB   510 pages   955,651 chars   1.3s  Hands-on machine learning.pdf
```

Both read on the first attempt. **Extraction is not the cost** — 1.3 s for a 510-page book — and that
is worth stating because it was the thing I expected to be slow. The cost is downstream: 956k
characters is roughly 1,400 chunks, a **13% increase in the corpus** from one file, all of it needing
embedding on first index.

`PyMuPDF` was rejected on licensing (AGPL, for a text extractor), `pdfminer.six` on speed, and OCR on
scope: a second model and a second failure mode for content this corpus does not contain. A scan is
reported as having no text layer, which is a better answer than a half-guessed one.

## Two decisions worth arguing about

**Pages are packed, not one chunk each.** A page is a printing artefact, not a unit of meaning — a
paragraph runs across the break and a heading sits at the bottom of the previous page. 510 one-page
chunks would be 510 embeddings of running text cut mid-sentence. Pages go through the same `_pack`
every other content type uses, so a chunk usually spans two or three of them.

The anchor is `p. 12`, and it is the *only* citation a PDF can offer that a reader can act on: there
is no heading path to recover and no symbol to name. `_render` writes each page's anchor into the
chunk text, so a chunk spanning pages 12–14 says so.

**Every PDF is `local_foreign`.** Nobody writes a PDF in Obsidian. Every one in this corpus is
something acquired — a textbook, a paper, a datasheet — so it is text by someone else, which is
exactly what the provenance flag means. Retrieved text is untrusted input
([SECURITY.md §6](../../docs/SECURITY.md#6-prompt-injection-and-taint-tracking)), and a 510-page book
is a large surface of prose that no one on this machine wrote.

It is a generalisation, and I could not find a way to detect authorship from a path that was not a
worse guess. The deciding argument is which direction it fails in: being wrong here **escalates** the
policy tier of any plan built on the content and never relaxes it. A user's own PDF being treated as
foreign costs a confirmation; a textbook being treated as owned costs the property the taint model
exists to provide.

## The fixtures are hand-built PDFs

`tests/test_rag_pdf.py` assembles minimal PDFs from raw syntax — catalog, pages, content streams,
xref table — rather than writing them with `pypdfium2`. Partly necessity: 5.x has no high-level
text-authoring API, so the alternative is a page of `raw` ctypes calls that would make the test a test
of pdfium's *writer*. Mostly principle: a fixture produced by the same library that reads it can hide
a bug the two share.

The failure cases are the point of that file. A PDF is the only content type here that can be
present, readable and **empty**, and "indexed nothing, said nothing" is the worst response to a scan —
the user sees a document they can open and never gets it back in an answer.
